# ADR-016 — FastMCP independente e serviços compartilháveis

**Status:** DECIDED — escolha do proprietário na entrevista M0.5, com desenho
consolidado aprovado em 2026-11-12. O spike M0.5 foi implementado e validado;
o transporte HTTP permanece para M4.

## Contexto

O projeto previa o SDK Python oficial para MCP, sem definir o framework de alto
nível. O proprietário escolheu o pacote independente `fastmcp`, distinguindo-o
do FastMCP incluído em versões antigas do SDK. A aplicação já usa FastAPI e deve
preservar a possibilidade de integrar o transporte MCP HTTP no M4.

## Decisão

- Usar `from fastmcp import FastMCP`, sobre o SDK MCP Python.
- M0.5 usa apenas `stdio`. O processo MCP chama Application Services Python
  autorizados diretamente, com contratos e repositório sintéticos isolados.
- Serviços permanecem independentes de FastMCP e FastAPI para compartilhamento
  futuro. Montagem MCP HTTP no FastAPI pertence ao M4.
- Não converter automaticamente toda a API REST em ferramentas MCP.
- M0.5 validou FastMCP 4.1.8 e SDK 2.3.0 em runtime, inclusive com as CLIs
  Hermes e Codex. O lock preservou os pins anteriores do monorepo.

## Alternativas e consequências

Usar diretamente o SDK oficial evitaria o framework adicional, mas o proprietário
escolheu FastMCP. A mediação REST interna pelo FastAPI foi considerada; chamadas
diretas evitam depender da API, seus endpoints e autenticação HTTP no spike.
O framework amplia dependências transitivas; fixar lock e testar protocolo, erros
sanitizados, autorização e logs na versão efetivamente instalada.

Os limites de navegador externo, relatos sem confirmação e transportes definidos
nos ADRs 004/005 continuam vigentes. A validação com Hermes e Codex cobre o
recorte sintético `stdio` de M0.5; não antecipa HTTP ou o catálogo completo V1.
